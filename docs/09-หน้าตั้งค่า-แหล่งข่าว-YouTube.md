## 4. แท็บ "YouTube · NotebookLM"

**ทำงานอย่างไร** (`tools/yt-digest.mjs`):

1. `yt-dlp` อ่านข้อมูลคลิปและคำบรรยายพร้อมเวลา (ใช้ subtitle ต้นฉบับหรือ auto-caption)
2. สรุปเป็นภาษาไทยแบบ JSON: สรุป, ประเด็นสำคัญพร้อมเวลา, มุมข่าว และข้ออ้างที่ต้องตรวจ
   - ถ้า NotebookLM ติดตั้งและล็อกอินแล้ว จะใช้ NotebookLM
   - ถ้ายังไม่พร้อม จะใช้ LLM ของบอท (ตอนนี้คือ qwen3.6)
   - ถ้า NotebookLM ล้มเหลว จะสลับไปใช้ LLM เอง
3. ดาวน์โหลดเฉพาะภาพวิดีโอ (≤720p) แล้วให้ `ffmpeg` จับภาพหน้าจอ ณ แต่ละประเด็น จากนั้นลบวิดีโอทิ้ง
   - ffmpeg อ่านจาก URL ของ YouTube ตรง ๆ จะค้าง เพราะ YouTube จำกัดความเร็ว จึงต้องดาวน์โหลดผ่าน yt-dlp ก่อน
4. บันทึกผลที่ `D:\AI-ART\BotPress\data\news\youtube\<videoId>\`: `digest.json`, `digest.md`, `transcript.txt` และ `frames/*.jpg`

**ผลทดสอบ:**

| The Best CPUs of 2026 (17 นาที) | 14.8 วินาที | 5 ประเด็น · 5 ภาพ (ภาพที่ 4:32 เป็นกล่อง Core Ultra 5 250K Plus ตรงกับประเด็น) |
| Ryzen 7 9850X3D Review (27 นาที) | ~20 วินาที | 7–9 ประเด็น · 6 ภาพ (กราฟเบนช์มาร์ก) |

**ปัญหาที่แก้ระหว่างทดสอบ:**

- qwen บางครั้ง:
  - ไม่ส่งประเด็นพร้อมเวลา → ระบบลองใหม่ 1 ครั้ง
  - ส่ง JSON ที่มี comma เกิน → ระบบแก้ให้เอง
  - ส่งเวลาเป็นช่วง เช่น "1:46-2:59" → ระบบใช้เวลาเริ่มต้น
- qwen เคยปน **คำภาษาจีนหรือเวียดนาม** มาในข้อความไทย ("ประสิทธิภาพ在游戏中", "tiêu thụ") ตอนนี้ถ้าตรวจเจอ ระบบจะส่งให้เขียนใหม่เป็นภาษาไทยอีก 1 รอบ และรอบทดสอบหลังแก้ไม่พบคำปนแล้ว

**บอทใช้อย่างไร:** เครื่องมือ MCP ใหม่ `youtube_digest(url, by)`

1. เรียกครั้งแรก = ส่งคำขอ (เขียนไฟล์ไว้ที่ `news/youtube/requests/`)
2. แอปบนเครื่องนี้หยิบคำขอไปทำทุก 15 วินาที
3. เรียกซ้ำด้วยลิงก์เดิม = ได้สรุป ประเด็น ชื่อไฟล์ภาพ และคำเตือนให้ใส่เครดิตช่องพร้อมลิงก์คลิปใน sources
4. ถ้าล้มเหลว บอทจะได้ข้อความสาเหตุ และเรียกใหม่ได้

ต้องเปิดแอป iHC-Press ไว้ตลอด เพราะบอทรัน yt-dlp เองไม่ได้ (เครื่องของบอทถูกจำกัดสิทธิ์)

**ลิขสิทธิ์:** ภาพหน้าจอเป็นของเจ้าของช่อง หน้าอ่านสรุปและข้อความที่ส่งให้บอทเตือนให้ใส่เครดิตและลิงก์ทุกครั้ง

## 5. ต้องติดตั้งอะไรเพื่อใช้ NotebookLM

NotebookLM (เปลี่ยนชื่อเป็น Gemini Notebook ตั้งแต่ ก.ค. 2026) **ไม่มี API ทางการสำหรับบัญชีทั่วไป** API ทางการมีเฉพาะ NotebookLM Enterprise บน Google Cloud ซึ่งต้องมีบัญชีองค์กร จึงต้องใช้ตัวเชื่อมโอเพนซอร์ส **notebooklm-py** (github.com/teng-lin/notebooklm-py)

| สิ่งที่ต้องมี | สถานะเครื่องนี้ |
|---|---|
| Node.js, yt-dlp, ffmpeg | ✅ มีแล้ว (ใช้ได้ทันทีด้วย LLM แม้ไม่มี NotebookLM) |
| uv (ตัวติดตั้งโปรแกรม Python) | ✅ uv 0.12.5 |
| `notebooklm-py[browser]` | ❌ ยังไม่ติดตั้ง ใช้ปุ่ม **ติดตั้ง** ในแอป หรือคำสั่ง `uv tool install "notebooklm-py[browser]"` |
| ล็อกอิน Google | ❌ ใช้ปุ่ม **เข้าสู่ระบบ Google** ในแอป (= `notebooklm login`) ครั้งแรกจะดาวน์โหลด Chromium ~170 MB แล้วเปิดให้ล็อกอิน |

เมื่อติดตั้งและล็อกอินแล้ว กด "ตรวจใหม่" ระบบจะเปลี่ยนตัวสรุปเป็น NotebookLM ให้อัตโนมัติ โดยทุกคลิปจะถูกเพิ่มเป็น source ใน notebook เดียวกันชื่อ "iHC-Press · YouTube"

**ข้อควรรู้:**

- notebooklm-py **ไม่ใช่ของ Google** มันใช้ API ภายในที่ Google เปลี่ยนได้ทุกเมื่อ และใช้หนักอาจโดนจำกัดความถี่
- แนะนำให้ใช้ **บัญชี Google แยก** สำหรับงานนี้ เพราะไฟล์ล็อกอินอยู่ที่ `~/.notebooklm/profiles/default/storage_state.json` ซึ่งมีสิทธิ์เต็มของบัญชีนั้น
- NotebookLM นำเข้า **เฉพาะคำบรรยาย (transcript)** ของคลิป ไม่ได้ดูภาพ ภาพหน้าจอจึงมาจาก yt-dlp + ffmpeg เสมอ
- คลิปที่เพิ่งอัปโหลดไม่ถึง 72 ชั่วโมง คลิป private และคลิป unlisted อาจนำเข้าไม่ได้
- ⚠ ส่วนที่เรียก NotebookLM ในสคริปต์ **ยังไม่ได้ทดสอบจริง** เพราะยังไม่ได้ติดตั้งและล็อกอิน ถ้าล้มเหลว ระบบจะใช้ LLM แทนเอง
